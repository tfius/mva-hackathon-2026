ligand-ai.org

The site is a programme page, not a data portal

Nothing is downloadable from ligand-ai.org itself. Every asset it describes is hosted elsewhere.

LIGAND-AI is an Innovative Health Initiative project (grant 101252959) led by Pfizer and the Structural Genomics Consortium, with partners across nine countries. The public site is a React SPA with seven content routes — /about, /work-packages, /partners, /resources, /protocol, /news, /contact. The news feed is empty ("check back soon"); /resources is a link board pointing outward.

The stated programme scope is worth knowing because it tells you what will land over the next few years: ligandability data for 2,000 purified human proteins by Enantioselective Affinity Selection Mass Spectrometry, at least 200 newly purified proteins, 500 community-contributed targets, two open-source DNA-encoded libraries, and open benchmarking runs with CASP, CACHE and DREAM. All of it is committed to release in "AI-ready formats" via AIRCHECK.

So the practical question — what can run here today — resolves entirely into AIRCHECK plus the code repos around it.

AIRCHECK · Challenges

Target 2035 PGK2 challenge data

A separate tab hosts benchmark-shaped data with train/test splits already defined. All three require an account (Baylor College of Medicine as provider):

  • PGK2 — target screen against the BCM OpenDEL screening libraries
  • PGK2_CACHE_Val_Test_Set — the validation and test split for the challenge
  • OpenDEL_libraries — building-block IDs and SMILES for all 12 OpenDEL libraries

This is the one part of AIRCHECK with a published evaluation protocol and gold labels, which makes it the natural place to calibrate a model against other people's numbers. Target2035_Aircheck_Utils ships the fingerprint extraction, parquet readers, a training notebook and the evaluation scripts.

HuggingFace · GitHub

Models and code that run locally

DELBERT — the strongest published baseline

A self-supervised transformer that treats molecular fingerprints as a discrete token language, masked-LM pretrained. It was designed for exactly AIRCHECK's constraint: screening data released as precomputed fingerprints without structures. Published at the ICLR 2026 MLGenX workshop; reported 1.6–2.7× improvement in early-enrichment metrics over XGBoost and LightGBM ensembles on three of four targets under library-based out-of-distribution evaluation.

External benchmarks worth pulling in

  • SAIR (SandboxAQ) — 1,048,857 unique protein-ligand pairs, 5.2 M 3D structures, co-folded with Boltz-1x and labelled with ChEMBL/BindingDB potency. CC BY 4.0, commercial use permitted. 811 GB on HuggingFace — the single largest thing in this document.
  • PLINDER — PDB-derived protein-ligand interaction dataset with published splits; the standard benchmark for docking generalization.
  • KinDEL (insitro) — 81 M DEL compounds with docking poses for MAPK14 and DDR1. Largest public DEL benchmark; a good generalization test for anything trained on AIRCHECK.
  • MMELON (IBM) — multi-view molecular foundation model, graph + image + text, pretrained on up to 200 M molecules.
  • MPDF — multimodal pretraining DEL-fusion for denoising non-specific DEL interactions.

Folding and co-folding: what is actually downloadable

"Download AlphaFold" resolves into three unrelated artifacts with three different access stories. Only one of them is gated.

ArtifactTermsAccess

For this programme the AlphaFold database matters more than the model. It already covers most of the 92 E-ASMS targets and will cover the incoming 2,000-protein set — retrieval beats folding when someone has already folded it.

Co-folding is the relevant capability

WP7 is pose and hit prediction, which needs protein and ligand folded together. Every serious open co-folder ships weights with no request step:

Database footprint

AF3's genetic databases are 252 GB compressed, 630 GB uncompressed, with ~1 TB recommended and SSD strongly preferred — MSA search is I/O-bound. AF2's full_dbs are larger still, dominated by BFD. Boltz and Chai sidestep this entirely by defaulting to a remote MSA server, or can point at local ColabFold/MMseqs2 databases. Roughly 20 GB gets all three co-folders running with no local database at all.

Hardware clears every bar: Blackwell is compute capability 12.0 against AF3's floor of 8.0, CUDA 13.3 is already installed, and 96 GB per card is well past the A100-80GB the documentation assumes — meaning noticeably larger complexes than the published limits. 123 GB system RAM exceeds the 64 GB recommended for genetic search.

The blueprint that matters

NVIDIA publishes a generative virtual screening blueprint chaining GenMol → DiffDock → Boltz-2: generate candidates, dock them, score binding affinity. That is a complete hit-expansion loop, and it is exactly the shape of WP4. Swap in a DEL-derived starting scaffold and the AIRCHECK ENRICHMENT column becomes your ground truth for calibrating it.

Licensing

Terms vary per repo and are not uniform. ReaSyn, KERMT and RNAPro are Apache-2.0; the ESM-2 mirrors are MIT; several others — Proteina, DualBind, nvDock, boltz-cp — carry non-standard or unstated licences on GitHub. Check the per-repo LICENSE and the model card before anything leaves research use. NIM containers are a separate distribution channel and need an NGC account and API key.

Mechanics

Getting the data

Programmatic access needs no account for the HitGen sets. The package resolves a dataset name to a signed GCS URL through a public endpoint, then streams the parquet.

# verified working on this machine, Python 3.14, clean venv
pip install aircheckdata

# list what the package indexes (HitGen only, 11 datasets)
python -c "from aircheckdata import list_datasets; print(list_datasets())"

# inspect the schema before pulling a gigabyte
python -c "from aircheckdata import get_columns; print(get_columns('HitGen','WDR91'))"
from aircheckdata import load_dataset

# pull only what the model needs — the FP columns are the bulk of the file
df = load_dataset(
    "HitGen", "WDR91",
    columns=["DEL_ID", "SMILES", "ECFP4", "FCFP6", "ATOMPAIR", "TOPTOR",
             "TARGET_VALUE", "NTC_VALUE", "ENRICHMENT", "LABEL"],
    show_progress=True,
)

Under the hood it POSTs {"company_name": ..., "target": ...} to a Cloud Run signed-URL service and reads the returned URL with PyArrow. If you want to fetch outside Python, that same endpoint gives you a plain HTTPS URL you can hand to curl or aria2c — which is the faster route for bulk mirroring across the new disks.

Licence

The HitGen DEL data is covered by the HitGen End User Licence Agreement. Read it before mirroring anything, and check its redistribution terms before any derived dataset leaves this machine. X-Chem and BCM data additionally require an AIRCHECK account.

E-ASMS datasets are downloaded from the web table rather than the package — the loader currently indexes DEL/HitGen only. 92 individual downloads is worth scripting against the same signed-URL service once you have the provider and target strings.

What is in a DEL parquet

22 columns. Structures are included for the HitGen sets — the fingerprints-only privacy mode that DELBERT was designed around applies to other providers.

The one real trap

The parquet files are compressed sparse fingerprints. Materializing nine dense 2048-wide FP columns as int32 is roughly 70 KB per row — over a multi-million-row screen that expands from under a gigabyte on disk into the terabyte range. Always pass columns=, and keep working sets as sparse arrays or memory-mapped shards. This is a working-set discipline, not a download-size problem.

With more disks going in, a sane layout is one volume for immutable raw mirrors (AIRCHECK parquet + HuggingFace cache, ~50 GB with headroom for the 2,000-protein E-ASMS release as it lands), and a separate fast volume for materialized training shards and MLflow artifacts, which is where the real growth happens.

Sequence

Suggested first runs

  1. Reproduce a published number

    Pull WDR91 (0.91 GB) and wanglab/delbert-wdr91, run inference on the raw parquet, and confirm the early-enrichment metric against the paper. This validates the whole chain — licence, loader, schema, model input format — before anything is trained.

  2. Establish the floor

    Train the LightGBM baseline via AIRCHECK-DEL-ML in fully-local mode on the same target and split. Now you have both ends of the published range on your own hardware.

  3. Train DELBERT from scratch

    Pretrain and finetune on the 6.77 GB tokenized corpus using library-based OOD splits on BB*_ID. One GPU per run, two runs concurrently.

  4. Exploit the paired screens

    The PLCZ1 family — with/without competing inhibitor, plus the PLCD1 off-target counter-screen — supports selectivity modelling that single-target datasets cannot. Nothing published uses it yet.

  5. Cross the modalities

    Seven proteins have both DEL and E-ASMS screens. Whether DEL-trained models transfer to E-ASMS hit calling on the same protein is an open question with the data already in hand.

  6. Add structure to the fingerprint models

    Retrieve AFDB structures for the DEL targets, co-fold the top-enriched compounds with Boltz-2, and check whether its affinity head agrees with the measured ENRICHMENT. That correlation is the gate on everything structure-based downstream.

  7. Close the generative loop

    Run GenMol → nvDock/DiffDock → Boltz-2 on a confirmed DEL hit, filter the output through ReaSyn for synthesizability, and you have a WP4 hit-expansion pipeline running end to end locally.

  8. Test generalization externally

    Score against KinDEL (MAPK14, DDR1), fine-tune the Boltz-2 affinity head on SAIR, and register for the Target 2035 PGK2 challenge, which has gold labels and a published evaluation protocol.
